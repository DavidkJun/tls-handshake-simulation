# Імітація TLS/SSL-рукостискання в розподіленій мережі вузлів

РГР з курсу «Безпека програмного забезпечення», КПІ ім. Ігоря Сікорського, ФІОТ.
Виконав: Крикота Давид, ІМ-33.

Node.js 20+, одна залежність: `node-forge` (лише для випуску X.509-сертифікатів; перевірка, RSA, AES-GCM і HMAC зроблені вбудованим `node:crypto`).

## Що реалізовано

- **Рукостискання TLS 1.2 з обміном ключами RSA** (`TLS_RSA_WITH_AES_128_GCM_SHA256`):
  ClientHello (client random) → ServerHello (server random + X.509-сертифікат) → перевірка сертифіката
  → premaster, зашифрований RSA-OAEP відкритим ключем сервера → master secret і сеансові ключі через
  PRF TLS 1.2 (P_SHA256) → Finished «ready», зашифрований сеансовим ключем, з verify_data → записи AES-128-GCM.
- **Центр сертифікації** — окремий HTTP-сервер: випускає сертифікати за CSR, перевіряє сертифікат
  (підпис кореневим ключем, строк дії, реєстр, відкликання), відкликає сертифікати.
- **Топологія з 7 вузлів** (не повнозв'язна), кожен вузол — TCP-сервер; рукостискання можливе між будь-якою парою,
  проміжні вузли пересилають зашифровані пакети, не знаючи ключів.
- **Повільний радіоканал**: кадр не більше 96 байт, затримка за швидкістю 57 600 біт/с, фрагментація і збирання.
- **Маршрутизація link-state**: оголошення про сусідів поширюються затопленням, маршрути — найкоротші шляхи (BFS);
  при падінні каналу маршрути перераховуються.
- **Бродкаст** деревом найкоротших шляхів від джерела: кожен вузол отримує повідомлення рівно один раз,
  кожен перехід захищений TLS-сесією, автентичність джерела — підпис RSA.
- **Передача даних** захищеним каналом: чат-повідомлення і текстовий файл з перевіркою SHA-256.
- **Сценарії атак**: підміна сертифіката (фальшивий CA, чужий сертифікат), зміна шифротексту, відкликаний сертифікат.

## Топологія

```
A ── B ── D ── F ── G
 \        |   /
  C ──────┘  /
   \        /
    E ─────┘
```
Канали: A–B, A–C, B–D, C–D, C–E, D–F, E–F, F–G (`src/config.js`).

## Запуск

```bash
npm install
npm test        # модульні тести: PRF, ключі, записи, сертифікати, радіоканал
npm run demo    # повний сценарій в одному процесі, лог: demo/output.log
```

Кожен вузол в окремому процесі (окремі термінали):

```bash
npm run ca
node src/cli.js A      # і так само B … G
```
Команди вузла: `routes`, `connect G`, `msg G текст`, `file G demo/message.txt`, `bcast текст`, `sessions`, `drop B`, `stats`.

## Структура

| Файл | Призначення |
|---|---|
| `src/tls.js` | PRF TLS 1.2, стан сесії, повідомлення рукостискання, record layer AES-GCM |
| `src/pki.js` | ключі RSA, CSR, кореневий сертифікат, випуск і перевірка X.509 |
| `src/ca.js`, `src/ca-server.js` | HTTP-сервер центру сертифікації |
| `src/link.js` | радіоканал: кадри ≤ MTU, затримка, фрагментація |
| `src/mesh-node.js` | вузол: маршрутизація, пересилання, TLS, чат, файли, бродкаст |
| `src/cli.js` | інтерактивний запуск одного вузла |
| `demo.js` | сценарій демонстрації |
